## 1. 这个产品是什么，值不值得用

### 1.1 定位（✅ 官方原文）

> 硬件对话智能体是一个端到端的智能硬件对话开发平台，兼容主流 IoT 芯片，可快速帮助开发者将低延迟、高自然的 AI 对话能力集成到智能硬件中，让智能硬件会听、会看、会说话，适用于 **AI 玩具**、智能穿戴设备、陪伴机器人、智能家居、教育硬件、具身智能设备等场景。

**与本项目的关系**：我们的「AI 智能玩具 SaaS 平台」正属于其目标场景（AI 玩具），且它同时提供「设备云」与「智能体编排」两层能力——这两层正好对应我们平台里的 `cloud_providers`（云服务商）与 `client_products`（客户产品的 AI 配置）。

### 1.2 关键指标（✅ 官方原文）

| 指标 | 数值 |
|---|---|
| 端到端响应时延 | **低于 1.6s** |
| SDK 内存占用 | 低负载方案 **< 100 KB**；高质量方案 **< 300 KB** |
| 降噪 | 音频 3A 技术 + AI 降噪（强降噪与高保真兼顾） |
| 打断能力 | 支持随时插话打断 |
| 模型编排 | 支持豆包、第三方及私有化部署模型；可视化编排；**兼容扣子（Coze）生态** |
| 芯片支持 | 乐鑫、博通集成、移芯、展锐、杰理、星宸、全志、君正、瑞芯微、安凯微、移远、广和通、安信可等 |

### 1.3 功能特性（✅ 官方原文摘要）

AI 实时语音对话 / 语音识别（ASR）/ 大模型处理（LLM）/ 语音合成（TTS）/ 降噪 / 打断智能体 / **视觉理解** / **Function calling** / **实时字幕**。

### 1.4 两条接入方案：必须先选一条

| 对比项 | 高质量方案 | 低负载方案 |
|---|---|---|
| 传输层协议 | **UDP（RTC 技术）** | **TCP（WebSocket）** |
| 建连延时 | 相对较高 | 更低（略优） |
| 传输延时 | **更低（更优）** | 相对较高 |
| 整体延时 | 无明显差异 | 无明显差异 |
| 弱网环境稳定性 | **抗弱网能力强**（带宽估计、纠错重传），显著更优 | 稳定性较差 |
| 优质网络稳定性 | 高可靠 | 高可靠 |
| 多媒体场景 | **显著更优**，适合音视频 | 表现较差，**建议仅用于音频场景** |
| 资源消耗 | 相对较高（RAM < 300KB） | **更低**（RAM < 100KB），适合低配置硬件 |
| 接入成本 | 无明显差异 | 无明显差异 |

**给本项目的选择建议**：
- AI 玩具（纯语音、成本敏感、MCU 资源有限）→ **低负载方案**
- 要加摄像头做视觉理解（如「会看」）→ **高质量方案**（官方明确：视频通信场景建议选高质量方案）

### 1.5 ⚠️ 一个极易踩的坑：不要和「AI 音视频互动方案」混用

✅ 官方原文：**两者是不同的 AI 语音对话智能体方案，拥有不同的产品 SDK 和 OpenAPI，不能混合使用。**

| 产品 | 适用场景 |
|---|---|
| AI 音视频互动方案 | AI 智能助手、AI 客服、AI 陪伴、AI 游戏 NPC 等**智能软件**场景 |
| **硬件对话智能体** | AI 玩具、智能眼镜、智能家居、具身智能等**智能硬件**场景 ← **本项目用这个** |

> ⚠️ 这意味着：网上搜到的「火山引擎实时对话式 AI / RTC 的 StartVoiceChat」那套 API **不适用**于本项目。硬件对话智能体走的是 `Aibot*` 系列（见 §5）。

## 3. 控制台配置全流程（含每一步的参数含义）

### 3.1 步骤 1：创建产品

**路径**：`智能硬件管理 > 产品管理 > + 创建产品`

| 配置项 | 说明 | 建议填法 |
|---|---|---|
| 所属实例 | 产品所属物联网实例 | 保持 `默认实例`，不要改 |
| 产品名称 | 产品的名称 | 用**能对应到业务的名字**，如 `小方块玩具` |

✅ 官方原文说明：**产品代表某一类具有相同功能和属性的硬件设备。** 通过创建产品、为产品分配 License 和扩展资源、关联智能体，可以为硬件设备**统一配置** AI 对话能力。

> **概念对齐（很重要）**：火山侧「产品 = 设备组 = 一类设备的配置模板」，同一产品下的所有设备共享该产品的智能体配置。这与我们平台里的 `product_templates`（产品模板）语义接近，而**不是** `client_products`（客户产品）。
>
> 更精确的映射见 §6。

### 3.2 步骤 2：分配 License（★ 今晚重点确认）

**为什么必须做**：✅ 官方原文——**当产品下的设备激活时，每台设备会自动绑定并使用一个 License。**

| 操作 | 路径 | 要点 |
|---|---|---|
| 分配 License | 产品列表 → 操作列 → `分配 License` | 选择一种**规格**并设置**数量** |
| 分配扩展资源 | 产品列表 → 操作列 → `...` → `分配扩展资源` | 按需，见下 |

**硬性规则（✅ 官方原文）**：
- **一个产品只能分配一种规格的 License**（规格如：基础版 / 高级版 / 尊享版），不同规格预置的**语音时长**与 **LLM Tokens** 额度不同。
- 规格与数量要按「设备销量预期 × 用户使用频度」来定。
- **License 和扩展资源都需要提前购买**（免费领取的另计）。
- **扩展资源**用于：① License 预置资源不足时扩容；② 开通**视觉理解**、**声音复刻**等扩展功能。扩展资源分配给产品后，**该产品下所有设备共享使用**。
- ⚠️ **一旦产品被分配了 License，该产品将无法删除**（不可逆）。

> **成本提示**：你有 10 个免费基础版 License（每个 9 小时语音 + 1350k tokens）。一台设备激活就吃掉 1 个。做硬件联调时**不要反复激活/注销**，否则额度消耗很快。

### 3.3 步骤 3：创建并关联智能体

**路径**：`智能体管理` → `创建智能体`

**实测该页字段**：`智能体名称` / `使用模型` / `音色`（列表列名即这三个）。

**智能体定义**（✅ 官方原文）：智能体定义了设备与用户进行语音对话的主要配置，包括**语音识别（ASR）、大模型（LLM）、语音合成（TTS）** 等基础能力，以及**视觉理解、Function Calling** 等扩展能力。

**关联路径**：产品列表 → `已关联智能体` 列 → `+ 关联智能体` → 勾选一个或多个智能体 → `关联`

**两条必须记住的规则（✅ 官方原文）**：
1. **设备仅能绑定与其所属产品关联的智能体。** → 所以「产品 ↔ 智能体」的关联没做，设备侧一定连不上。
2. ⚠️ **取消产品与智能体的关联后，绑定该智能体的所有设备将无法与用户进行 AI 对话。** → 生产环境慎操作。

**⚠️ 控制台的能力边界**（这里是最容易误解的一点，✅ 官方原文）：

| | 平台智能体 | 设备智能体（用户自定义） |
|---|---|---|
| 绑定及作用范围 | **产品**（设备组）——与产品绑定后对该产品下**所有设备**生效 | **设备**——仅与该智能体绑定的设备拥有其 AI 能力 |
| 创建方 | B 端客户（你） | C 端用户（你的终端用户） |
| 实现方式 | 后端服务直接调用 API | 终端 App 请求你的后端 → 你的后端调用 API 实时创建 |
| 控制台管理 | **支持创建/编辑** | **仅支持查看，不支持编辑** |

> **对我们的产品意义重大**：控制台**只能创建平台智能体**。如果我们的 SaaS 要让「每个商户 / 每台设备拥有自己的专属人设」，就必须在**我们自己的后端**调用 `AibotCreate`（`AccessType=private`）——这正是 P7 阶段 `volcano` 适配器要干的事。

## 4. 设备端接入（ESP32-S3）

> ★★★ **路线决策更新（2026-09-20，先读这一段再往下看）**：
> 本项目已定案走 **路线 B——复用本机已实测跑通的固件、只换协议层**（火山「标准协议自定义接入」WebSocket + **后端代注册**，`product_secret` 不出后端），
> 完整规格、签名细节与改动清单见 **[`16-火山标准协议设备端接入方案与改动清单.md`](./16-火山标准协议设备端接入方案与改动清单.md)**。
> 另经克隆官方 `rtc-aigc-embedded-demo` 仓库逐文件核实：**本节 4.1/4.2 的 `volc_*` API 名来自官方《移植指南》文档，
> 而官方 demo 里真实头文件（`VolcEngineRTCLite.h`）用的是 `byte_rtc_*` 系列接口**——
> 两者可能分属不同层（移植指南的传输层 vs 上层 Lite SDK），本节未再逐字核对；
> **照本节写代码前，一律以 `docs/16` 与官方头文件为准**。且官方 demo 走的是 RTC（高质量方案），
> 与本项目定案的 WebSocket 低负载路线不同。

### 4.1 交互流程总览（✅ 官方原文流程）

```
1. 初始化       应用层准备 config_json（含 ProductKey、Secret 等鉴权信息）
                注册 volc_event_handler_t 回调结构体
                调用 volc_create 创建引擎实例
2. 建立连接     调用 volc_start 启动智能体（SDK 自动鉴权 + 建长连接）
                触发 on_volc_event(CONNECTED)
                触发 on_volc_conversation_status(LISTENING)
3. 对话交互循环 上行：volc_send_audio_data（音频）/ volc_send_video_data（视频帧）
                下行：状态 THINKING → SPEAKING
                      on_volc_audio_data  （音频流 → 应用层播放）
                      on_volc_video_data  （视频流 → 应用层渲染）
                      on_volc_message_data（字幕 / 指令 → 应用层展示或处理）
4. 结束与释放   调用 volc_stop → 触发 IDLE 与 DISCONNECTED
                调用 volc_destroy 销毁实例并释放资源
```

**⚠️ 联调时最该盯的两行日志**：`on_volc_event(CONNECTED)` 与 `on_volc_conversation_status(LISTENING)`。
前者没有 → 网络/凭证问题；后者没有 → 智能体或 License 问题。

### 4.2 客户端 API 与回调清单（✅ 官方原文，C SDK 接口名）

| **乐鑫 ESP32-S3-Korvo-2** | 官方演示板 |

> **建议策略**：即使你手上是 Sense 板，若有条件也先用 EchoEar/Korvo-2 跑一次——目的是**把「账号 → 产品 → License → 智能体 → 对话」这条链路先跑通**，把问题域从「云端 + 硬件」缩小到「纯硬件移植」。

### 4.4 路径 B：预编译体验包（针对 ESP32-S3-EchoEar）

✅ 官方原文照录（**注意：这是针对喵伴板的体验包，不是通用包**）。

**前置准备**：ESP32-S3-EchoEar 开发板 + USB A 转 Micro-B 数据线 + 可运行 Python 3 的电脑。

**内置免费额度**：2 小时 AI 语音对话 + 30 万 Tokens；支持联网搜索查询、AI 音乐、音量调节、本地语音唤醒。

**烧录命令**（官方原文）：

```bash
pip3 install esptool
python3 -m esptool --chip esp32s3 -b 460800 --before=default_reset --after=hard_reset \
  write_flash --flash_mode dout --flash_freq 80m --flash_size detect \
  0x0 bootloader.bin \
  0x10000 VolcRTCDemo.bin \
  0x8000 partition-table.bin \
  0x510000 srmodels.bin \
  0xb2e000 eaf.bin
```

**Wi-Fi 配网（官方原文）**：

1. 手机 Wi-Fi 里找到名为 `VolcConvAl-XXXXXX` 的热点并连接（**热点密码与 Wi-Fi 名称相同**）
2. 手机浏览器访问 `http://192.168.4.1` 进入配网页
3. 填入要连接的 Wi-Fi 名称与密码并提交
4. ⚠️ **换 Wi-Fi 需先重启设备**；若重启后 30 秒内连不上已保存的 Wi-Fi，设备会**自动重新进入配网模式**（重复上述步骤即可）

> ⚠️ 官方也声明：**体验包仅供快速体验**，不保证高并发下的稳定性，**无法修改智能体音色、人设、function call**。要二次开发或上线请用开源示例工程。

### 4.5 路径 C：你的 ESP32-S3 Sense（需要移植，工作量最大）

**好消息**：移植依赖的闭源库 `volc_rtc_engine`，SDK **已内置 `macOS` / `ESP32-S3` / `ESP32-P4` 三个平台的静态库**（✅ 官方原文）。**你的板子芯片是 ESP32-S3，架构匹配，不需要向官方申请其它架构的静态库。**

**坏消息**：架构匹配 ≠ 开箱可用。官方 Demo 工程适配的是 EchoEar / Korvo-2 的**具体音频硬件（麦克风阵列 + 编解码 + 功放）**。Sense 板的音频链路（PDM/I2S 麦克风、编解码芯片、喇叭）需要你自己接。

**移植需要做的事（✅ 官方原文的任务划分）**：

| 类别 | 内容 |
|---|---|
| 直接引用（无需修改） | `volc_rtc_engine`（位于 `src/transports/high_quality/third_party/volc_rtc_engine_lite`）；连接逻辑（已归类在 `cmake/common.cmake`） |
| 需引入的外部依赖 | `mbedtls`（加密传输）、`cJSON`（JSON 解析，源码在 `src/util/cJSON`） |
| **需要自己实现（重点）** | ① **系统抽象层（OSAL）**：按 `osal/inc` 的接口定义实现线程、互斥锁、内存分配等（`osal/src` 有 Linux 参考实现）；② **配置构建脚本**：改 CMake 适配你的交叉编译工具链；③ **音频采集与播放链路**（官方文档未展开，属于芯片侧适配工作） |

**移植目标**（官方原文）：在你的目标平台上**构建出静态库并跑通连接测试**。

**⚠️ 替代路线（如果移植成本太高）**：
选**低负载方案**，即「**通过标准协议自定义接入**」（基于 WebSocket）。官方说明：如果硬件平台暂未被 SDK 支持，或需要深度定制底层通信，可基于 WebSocket 标准协议自行封装；代价是**需要自行处理鉴权签名、连接保活、协议封装**。对 Sense 板这类「芯片支持但板级音频链路不匹配」的情况，这条路往往比移植 C SDK 更快出成果。

### 4.6 三条路径怎么选（决策表）

| 你的情况 | 建议路径 | 预计今晚能否出结果 |
|---|---|---|
| 有 EchoEar / Korvo-2 板 | 路径 A（开源工程）或路径 B（体验包） | **能**，30 分钟内可听到对话 |
| 只有 ESP32-S3 Sense，且只想先听个响 | 先确认 Sense 是否有官方适配；没有就走**低负载方案 + WebSocket** | 较难，属于开发任务 |
| 只有 ESP32-S3 Sense，且愿意做 C 移植 | 路径 C（先跑通 `sample.c` 的连接测试，再补音频链路） | 不建议今晚承诺 |

### 5.3 `AibotCreate` 请求结构（✅ 官方文档原文摘要）

**Query 参数**：`Action=AibotCreate`（必选）、`Version=2025-08-01`（必选）

**Body 主要字段**：

| 字段 | 类型 | 必选 | 说明 |
|---|---|---|---|
| `Name` | String | 是 | 智能体名称，例如 `客服机器人` |
| `AccessType` | String | 是 | `public` = **平台智能体**（可关联到产品并在控制台管理）；`private` = **设备智能体**（只能绑定到设备，不支持控制台编辑） |
| `Config` | Object | 是 | 交互服务配置，包含 ASR / TTS / LLM / 字幕 / Function Calling / 音乐播放（MusicAgent）等 |
| `Config.ASRConfig` | Object | 是 | 语音识别配置 |
| `Config.ASRConfig.Provider` | String | 是 | 固定 `volcano`（火山引擎语音识别服务） |
| `Config.ASRConfig.ProviderParams` | Object | 是 | 随所选服务不同而不同；如 `ApiResourceId` 指定流式语音识别服务版本（示例值 `volc.bigasr.sauc.duration`） |

> TTS 侧可见的模型取值示例：`seed-tts-1.0` 或 `volc.service_type.10029`（语音合成大模型 1.0 字符版）——✅ 官方文档原文。
>
> LLM 侧可见字段：`ModelName`、`UserPrompts`（含 `Role`，可作 System / User 角色预设 Prompt 以增强回复质量）——✅ 官方文档原文。

**⚠️ 读法提醒**：`AibotCreate` 的完整字段表非常长（官方页面含数百个配置项，覆盖字幕标点过滤、Coze 变量赋值、联网工具描述、音乐、函数调用 JSON Schema 等）。**不要试图一次性全实现**——本项目 P7 只需先打通「最小可用集」：`Name` + `AccessType` + `ASRConfig` + `TTSConfig` + `LLMConfig`，其余按需增量。

### 5.4 服务端与设备端的职责分工（务必分清）

| 能力 | 谁来做 |
|---|---|
| 实时对话（ASR → LLM → TTS） | **设备端 SDK** 负责（`volc_start` 之后自动完成） |
| 创建 / 修改智能体 | **服务端**（`AibotCreate` / `AibotUpdate`） |

| 用量统计 / License 状态 | 控制台查看；服务端可通过回调（⚠️ 待校对） |

## 6. 与本项目（ToyVerse Cloud）的对接映射

### 6.1 对象映射表

| 火山引擎侧对象 | 本项目数据对象 | 表 | 说明 |
|---|---|---|---|
| 控制台账号（AK/SK）+ 实例 | `cloud_providers`（`vendor = VOLCANO`） | `cloud_providers` | 一个云服务商账号一行，密钥**加密落库**，响应只回掩码 |
| 产品（设备组） | `product_templates` | `product_templates` | 产品的「型号 + 芯片方案 + 联网方式 + 固件版本 + AI 能力」抽象 |
| 产品 ↔ 智能体 关联 | `product_templates.cloud_provider_id` | — | 模板绑定到某个云服务商账号 |
| 平台智能体 | `product_templates.ai_features` 配置快照 | — | P7 起由 `volcano` 适配器创建并回填 |
| License 规格 / 数量 | ⚠️ 待设计（P9 运营看板或 `cloud_providers.extra_config`） | — | 需要记录「已购 / 已分配 / 已消耗」以免超卖 |
| 设备 | `devices`（P4/P5 落地） | `devices` | 设备激活状态、在线状态等 |
| 租户（我们的多租户） | `tenants` → `client_products` | `client_products` | **火山侧无租户概念**，多租户隔离完全由我们平台层承担 |

### 6.2 ★ 关键设计结论：火山侧是「单账号」，多租户必须由我们兜住

火山引擎的账号模型是「**一个账号 → 多个实例 → 多个产品 → 多个设备**」，**没有租户维度**。而我们的平台是**多租户 SaaS**。

因此：
- **不能**让商户直接用火山账号 → 商户产品必须映射到我们平台的 `client_products`（带 `tenant_id`，NOT NULL）。
- 我们的平台后端作为**唯一的云服务商调用方**，用平台级 AK/SK 代所有租户调用 `Aibot*` 接口，并在 `ProductAuthorization`（产品授权）里控制「哪个租户可以用哪个模板」。
- 设备维度的访问控制（设备仅能绑定所属产品关联的智能体）由火山侧保证；**跨租户越权**由我们的 `app/db/scope.py` 租户作用域收口保证（ADR-08）。

> 这一条已经落在代码里：`backend/app/models/catalog.py` 的 `ClientProduct.tenant_id` 为 `NOT NULL`，且创建时必须校验授权（修复遗留缺陷 P-03）。

### 6.3 `.env` 配置对照（本项目）

```ini
# 火山引擎（豆包 / 硬件对话智能体）
VOLCANO_API_BASE=https://rtc.volcengineapi.com    # 服务端 OpenAPI 基址
VOLCANO_ACCESS_KEY=<控制台 API 密钥管理里的 AccessKey>
VOLCANO_SECRET_KEY=<控制台 API 密钥管理里的 SecretKey>
VOLCANO_APP_ID=<控制台账号 ID，实测为 2104193174>
VOLCANO_MODEL_ENDPOINT=<TTS/LLM 模型或 Cluster ID，见官方「模型列表和 Cluster ID」>
VOLCANO_TIMEOUT_SECONDS=30
```

**架构红线（ADR-07）**：**未配置密钥时，`health_check` 一律返回 DOWN，相关端点返回 `VENDOR_UNAVAILABLE`，绝不伪造成功。** 所以你在 `.env` 里没填 `VOLCANO_ACCESS_KEY/SECRET_KEY` 之前，平台端会明确告诉你「该能力已安全禁用」，而不是假装调用成功——这是有意为之的设计。

## 8. 排错速查表

| 现象 | 最可能的原因 | 排查动作 |
|---|---|---|
| 设备连不上 / 无 `CONNECTED` | Wi-Fi 未配网成功、或 ProductKey/Secret 错误 | 重启设备重进配网模式（30 秒规则）；核对产品详情页的 ProductKey / ProductSecret |
| 有 `CONNECTED` 但无 `LISTENING` | 产品**未关联智能体**，或**未分配 License** | 控制台检查「已关联智能体」列与 License 分配状态 |
| 能连上但设备无应答 | 智能体的 **LLM / TTS 未配置**，或 License 预置资源耗尽 | 智能体管理里检查使用模型与音色；设备详情页看「用量统计」进度条 |
| 对话中途断开 | 弱网（低负载方案对弱网不友好） | 换高质量方案，或改善网络 |
| 用量消耗异常快 | 语音时长按「交互时长」计费，联调反复激活/长时间挂机都会吃额度 | 设备详情页看「语音时长（小时）」「LLM（千tokens）」进度条 |
| 想改音色改不了 | 用的是**体验包**（官方明确不支持修改音色/人设/function call） | 改用开源示例工程；或在平台侧走 `AibotCreate` 自定义 |
| 想删除产品删不掉 | **已分配 License 的产品不可删除** | 这是官方约束，只能新建产品 |

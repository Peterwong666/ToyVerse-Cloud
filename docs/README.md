## 4. 文档与代码的一致性如何保证

文档最大的风险是**悄悄过期**：代码改了、文档没改，读者照着文档做会失败。
本项目用一个可执行的门禁来防这件事：

```bash
make docs-check     # 校验文档与代码是否一致
```

它做六件事（对应 `scripts/check_docs.py`）：

| # | 校验 | 不一致的后果 |
|---|---|---|
| 1 | `06-API接口文档.md` 里出现的每个 `METHOD /path` 都能在 OpenAPI 快照里找到，且**声明的端点总数与快照一致** | 读者照文档调接口会 404 |
| 2 | `05-数据模型与ER图.md` 里出现的每个表名都在迁移/模型集合里，且总数一致（46） | 读者照文档写 SQL 会报表不存在 |
| 3 | 文档里提到的每个错误码都在 `ErrorCode` 里（31 个） | 前端按错误码做的分支永不命中 |
| 4 | `07-多租户与权限设计.md` 里提到的每个权限码都在 `permissions.py` 注册（54 个） | 配权限时发现码不存在 |
| 5 | 文档里引用的每条命令、脚本文件与相对文档链接**真实存在**（不存在的目标会让读者照着做时失败） | 链接 404、命令报 no rule |
| 6 | 每份文档都含「已知局限 / 取证边界」小节，且**任何文档都不含 `learning/` 路径** | 边界声明被漏写；不该上传的目录被引用 |

> **为什么要专门做这个**：本项目的既定做法是「验收必须实测」，文档也不例外——
> 与其靠人记得同步，不如让不一致直接**红灯**。这与 `make fe-check`（前端导入契约）、
> `make openapi-check`（接口契约）是同一套思路。

## 5. 阅读约定

- **反引号包住一切代码标识符**：表名（`client_products`）、字段（`tenant_id`）、端点（`GET /merchant/products`）、
  错误码（`VENDOR_UNAVAILABLE`）、配置键（`JWT_SECRET_KEY`）、状态枚举（`IN_STOCK`）、迁移编号（`0015_ops_metrics_ota`）。
- **「」包住界面与概念文案**：如「已关联智能体」「设备四维」「未知」。
- **功能符号的含义**：

| 符号 | 含义 |
|---|---|
| `✅` | 已实测或有代码原文可查 |
| `⚠️` | 未验证 / 待联调 / 未实现 |
| `★` | 重点章节或关键交付物 |
| `🔑` | 关键节点，做错会阻塞后续 |
| `✔` / `✘` | 通过 / 失败 |
| `—` | 无 / 不适用 |

- **四档状态用语**（严格区分，不含糊）：**已实测** / **已实现但未联调** / **未实现** / **未取证**。
- **阶段与缺陷编号不混用**：`P0`–`P11` 是开发阶段；`P-01`–`P-08` 是遗留缺陷编号；`ADR-01`–`ADR-10` 是架构决策；`F-01`–`F-10` 是联调失败码。

## 附录：已知局限与取证边界

1. **本套文档是项目完成后回填的，不是事前设计稿**。`04-产品需求文档PRD.md` 描述的是**已交付**能力，
   而非立项时的需求假设；缺少用户调研、竞品数据与真实甲方验收记录。
   → 后果：不能据此判断「这个需求是否值得做」，只能判断「这个系统做到了什么」。
   → 补齐方式：若要作为真实产品立项，需补用户访谈与需求优先级排序。
2. **文档的数字由 `scripts/check_docs.py` 校验，但叙述性描述无法自动校验**。
   门禁能保证「表名/端点/错误码/权限码/链接」不错，**不能**保证某段业务解释仍然正确。
   → 补齐方式：改动业务语义时，把对应文档加入 PR 的必改清单（`CONTRIBUTING.md` 的评审要求）。
3. **`docs/assets/` 目前为空**：本项目文档集**不含截图**。
   → 后果：读者看不到界面长什么样，需要自己跑起来。
   → 补齐方式：计划在收尾阶段补各端关键页面截图（属未完成的 P11-C 范围）。
4. **涉及真实厂商的部分均未联调**（无任何厂商密钥）：`08`、`13`、`14` 的厂商相关内容
   只到「按官方文档封装 + 控制台实测」的程度，**签名算法与部分字段名仍是占位**。
   → 详见 [`13-火山引擎硬件对话智能体配置说明.md`](./13-火山引擎硬件对话智能体配置说明.md) 的取证边界附录。
5. **`10-AI验证可用性.md` 的基准数据来自离线模拟引擎**，不是真实厂商链路的性能。
   → 后果：这些数字**不能**用来评估真实上线的延迟与意图命中率。
   → 补齐方式：填入厂商密钥后按 `10` 的复现命令重测。
6. **P11 尚未全部完成**：学习手册（`learning/`，不上传 GitHub）与截图收尾不在本次文档集范围内。

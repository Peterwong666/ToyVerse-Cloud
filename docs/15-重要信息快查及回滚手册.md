## 0. 使用边界（先读这段）

- 本手册只写**位置、命令、判断依据**，**不写任何密钥/口令的值**。
  所有凭证一律在仓库根目录 `.env`（已被 `.gitignore` 排除，**不要提交**）。
- 本仓库是**公开仓库**。往这里写内容时，
  **不要把 Wi-Fi 口令、AK/SK、ProductSecret、DeviceSecret 等真实值写进任何会被提交的文件**。
- 带 `~` 的路径是**本机专属**，不在仓库里，克隆到别的机器上不会自动存在。

## 1. 一页速查

### 1.1 工具链

| 项 | 值 |
|---|---|
| ESP-IDF | **v6.1**，位于 `~/esp/esp-idf` |
| 工具链体积 | `~/.espressif`（约 4.8 GB） |
| 激活命令 | `get_idf`（= `. ~/esp/esp-idf/export.sh`，已写入 `~/.bashrc`） |
| 验证 | `get_idf && idf.py --version` → `ESP-IDF v6.1` |
| 编译器 | `xtensa-esp32-elf-gcc` 15.2.0 |
| 串口权限 | 用户需在 `dialout` 组（本机已加，**新会话生效**） |

> 装法（重建时用）：
> `git clone -b v6.1 --single-branch --depth 1 --shallow-submodules --recursive
> https://github.com/espressif/esp-idf.git ~/esp/esp-idf`
> 然后 `IDF_GITHUB_ASSETS=dl.espressif.cn/github_assets PIP_INDEX_URL=<国内 PyPI 镜像>
> ./install.sh esp32s3`。

### 1.2 固件工程

| 项 | 值 |
|---|---|
| 源码 | `~/esp/xiaozhi-esp32`（第三方开源语音助手固件） |
| 板型 | `seeed/xiao-esp32s3-sense`（本项目自建，**未提交上游**） |
| 编译 | `cd ~/esp/xiaozhi-esp32 && get_idf && python3 scripts/"build.py" seeed/xiao-esp32s3-sense` |
| 编译耗时 | 4 核约 15–21 分钟 |
| 产物 | `build/xiaozhi.bin`（约 2.05 MB）、`build/merged-binary.bin`（约 6.5 MB，整片烧录） |
| 烧录 | `idf.py -p /dev/ttyACM0 flash monitor` |

> ⚠️ **必须用固件工程自带的构建脚本（`scripts` 目录下的 `build.py`），不要用裸 `idf.py build`**：
> 板级的 `sdkconfig_append`（8 MB 分区表、LVGL 分配器等）只有该构建脚本会注入，
> 裸 `idf.py build` 会得到错误的分区表。

### 1.3 硬件与串口

| 项 | 值 |
|---|---|
| 板子 | Seeed **XIAO ESP32S3 Sense**（8 MB Flash + 8 MB Octal PSRAM） |
| 功放 | 外接 **MAX98357**（需独立 5V 供电） |
| 串口 | `/dev/ttyACM0`（USB-Serial/JTAG） |
| MAC | `1c:db:d4:75:a4:a4` |
| 烧录工具 | `~/.../idf6.1_py3.12_env/bin/python -m esptool`（esptool 5.4.0，随 IDF 安装） |

### 1.4 接线（已实测）

| 功能 | GPIO |
|---|---|
| MAX98357 BCLK | GPIO4 |
| MAX98357 LRC | GPIO5 |
| MAX98357 DIN | GPIO6 |

| 板载 PDM 麦克风 CLK | GPIO42 |
| 用户 LED（低电平点亮） | GPIO21 |
| BOOT 按键 | GPIO0 |

## 2. 回滚手册

> 原则：**任何写操作之前先备份**。下面的每条都给「判断依据 → 命令 → 验证」。

### 2.1 回滚固件到刷机前的原厂版本

**什么时候用**：小智固件跑不通、想回到板子出厂状态、或要交给别人时。

```bash
cd ~/esp/xiaozhi-esp32 && get_idf
PY=$HOME/.espressif/python_env/idf6.1_py3.12_env/bin/python

# 1) 整片擦除（会清掉 WiFi 凭据与 NVS）
sg dialout -c "$PY -m esptool --chip esp32s3 --port /dev/ttyACM0 erase-flash"

# 2) 写回原厂备份
sg dialout -c "$PY -m esptool --chip esp32s3 --port /dev/ttyACM0 -b 921600 \
  write-flash 0x0 ~/esp/backups/backup_before_xiaozhi_20260920.bin"
```

**验证**：`idf.py monitor` 应看到原厂固件启动；或重新 `flash_id` 确认芯片可读。

> 没有 `sg dialout` 也不用慌：本机 `/dev/ttyACM0` 的 ACL 已直接授予当前用户读写，
> `sg` 只是为了兼容「新会话未重登录」的情况。

### 2.2 回滚小智固件到上一次编译的版本

小智每次 `build.py` 都会覆盖 `build/`。**`build/` 没有版本历史**，
所以回滚只能靠「重新编译指定 commit」。

```bash
cd ~/esp/xiaozhi-esp32
git log --oneline -5          # 找到目标 commit
git checkout <commit>         # 或 git revert <坏提交>
python3 scripts/"build.py" seeed/xiao-esp32s3-sense
```

本项目在该工程的本地提交（**未推上游**）：

| commit | 内容 |
|---|---|
| `52160ed` | 新增 `seeed/xiao-esp32s3-sense` 板型 |
| `f1e9004` | 修复无屏板型的 LVGL 分配器崩溃 |

### 2.3 恢复「配网模式」（清掉已保存的 Wi-Fi）

**什么时候用**：想换 Wi-Fi、或设备连不上网一直在重试。

- **首选：清 NVS 分区**（保留固件，最快）
  ```bash
  sg dialout -c "$PY -m esptool --chip esp32s3 --port /dev/ttyACM0 erase-region 0x9000 0x4000"
  ```
- **备选：整片擦除后重刷**（见 2.1 第 1 步 + 重刷小智固件）

**重新配网**：手机连热点 `Xiaozhi-XXXX`（XXXX 取自 MAC 后两位），
浏览器打开 `http://192.168.4.1`，填 Wi-Fi 名称与口令。

### 2.4 回滚 ESP-IDF 本身

```bash
rm -rf ~/esp/esp-idf            # 只删源码，不动工具链
# 彻底重来才需要（会丢 4.8GB 已下载工具链，重新 install.sh 要等很久）：
rm -rf ~/.espressif
```

删掉后按 §1.1 的「装法」重建。**风险**：`~/.espressif` 删除后，
`get_idf` 会失败直到重跑 `install.sh`。

### 2.5 改动前的自检（推荐养成习惯）

```bash
cd ~/esp/xiaozhi-esp32 && git status --short
ls -la ~/esp/backups/          # 确认备份还在
```

## 3. 已知坑速查（现象 → 原因 → 对策）

| 现象 | 最可能原因 | 对策 |
|---|---|---|
| 配网成功后**反复重启**，日志 `Guru Meditation: LoadProhibited` | 无屏板型 LVGL 内存池未初始化 | 确认板型 `sdkconfig_append` 含 `CONFIG_LV_USE_BUILTIN_MALLOC=n` + `CONFIG_LV_USE_CLIB_MALLOC=y`（根因与解栈过程见 `项目进度.md` 的「硬件联调记录」） |
| 串口抓取中途断掉 | 按了 **RESET**（USB 会重新枚举）或芯片重启 | 用 `~/esp/serial_watch.py`（抗重枚举）；按键用 **BOOT** 别用 RESET |
| 打开串口后设备立刻重启 | pyserial 打开时拉低 DTR/RTS 会复位芯片 | 正常现象；脚本里已 `setDTR(False)/setRTS(False)` |
| `Permission denied` 读串口 | 不在 `dialout` 组且 ACL 未生效 | 重新登录，或命令前加 `sg dialout -c "..."` |
| 扬声器无声 | MAX98357 未独立 5V 供电 / SD 脚被拉低 | 先查供电，再查接线 |
| `esptool` 报未知选项 | v5 起参数**必须放在子命令之后** | `... write-flash --flash-mode dio ... 0x0 file.bin` |
| 编译报 `Invalid board configuration` | `config.json` 写了 `manufacturer` 但目录不在厂商子目录下 | 移到 `main/boards/<manufacturer>/<board>/` |

## 4. 排错方法论（可复用的两条）

1. **panic 不要靠猜**：把日志里 `Backtrace:` 的地址交给
   ```bash
   xtensa-esp32-elf-addr2line -pfiaC -e build/xiaozhi.elf <地址...>
   ```
   一步就能落回源码行。本项目那个「配网后必崩」就是这么定位的。

2. **怀疑硬件时，先隔离变量**：写一个**最小独立固件**只测那一件事
   （如 `~/esp/mic_test/` 只读 PDM 打 RMS），
   避免在几百个组件的大工程里排查。**注意它会覆盖现有固件**。

## 5. 已知局限与取证边界

本手册的内容**全部来自 2026-09-20 这一次真机操作的实测**，取证边界如下：

| 结论 | 取证方式 | 强度 |
|---|---|---|
| 板型为 XIAO ESP32S3 Sense、8 MB Flash + 8 MB PSRAM | `esptool flash_id` + 芯片特性行输出 | 工具直读，强 |
| PDM 麦克风引脚 DATA=41 / CLK=42 | Seeed 官方 wiki 表格与示例代码（`I2S.setAllPins(-1, 42, 41, -1, -1)`）交叉确认 | 官方文档，强 |
| 麦克风可用（50 cm 可唤醒） | 真机实测，用户确认 | 人工观察，中 |
| MAX98357 出声正常 | 真机实测，用户确认 | 人工观察，中 |
| 用户 LED 极性为「低电平点亮」 | 仅依 Seeed wiki 描述，**本机未实测** | 未取证 |
| MAX98357 需独立 5V 供电 | 常见工程经验，**本次未单独做供电对照实验** | 未取证 |

**已知局限**：

- 本手册针对**本机这一块特定的板子**（MAC `1c:db:d4:75:a4:a4`）。
  换一块同型号板子，串口设备名与回滚备份**都不通用**。
- §2 的回滚命令**没有在回滚方向上完整演练过**
  （备份文件的写入路径来自刷机前的读取操作，方向相反）。
  真正执行回滚前，建议先确认备份文件可读、大小与非空。
- 唤醒词、提示音等音频结论是在**特定固件版本**下取得的；
  固件升级后需重新验证。
- 本手册**不含**任何密钥与口令，因此也**不能**作为「凭证在哪」的唯一依据——
  凭证以 `.env` 与云控制台为准。

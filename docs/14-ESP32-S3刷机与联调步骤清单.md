# ESP32-S3 刷机与联调步骤清单（操作手册）

> **配套文档**：概念与取证说明见 [`13-火山引擎硬件对话智能体配置说明.md`](./13-火山引擎硬件对话智能体配置说明.md)
> **本文定位**：**照着做就行**的执行清单。每步都给出「怎么做 → 预期看到什么 → 不对时先查哪一条」。
> **适用硬件**：ESP32-S3 系列（含 ESP32-S3 Sense）
> **建议总时长**：云端链路 20 分钟（不碰硬件）＋ 硬件链路 30 分钟～数小时（取决于是否为官方 Demo 板）

├── 有 ──→ 走【路径 A】或【路径 B】，今天基本能听到对话 ✅

          ├── 愿意做 C 移植 ──→ 【路径 C】，今天目标只到「构建出静态库 + 连接测试通过」
          └── 想更快听到声音 ──→ 【路径 D】低负载方案（WebSocket 标准协议），

**今天的现实目标建议**（按优先级）：

2. **尽量达成**：任意一块板子能听到一句对话回应。
3. **可选**：把设备信息回填到本项目平台侧（步骤 8）。

## 1. 云端链路自检（20 分钟，**先做这一步，不要先焊板子**）

> 先跑通云端的好处：把「账号/授权/额度」这一层的不确定性清掉，后面硬件出问题时能立刻确定「不是云的问题」。

### 1.1 控制台：确认四步已就绪

| # | 操作 | 预期看到 | 不对时查 |
|---|---|---|---|
| 1 | 打开 `https://console.volcengine.com/conversational-ai-embedded/overview` | 首屏显示「10 个免费基础版 License」等额度信息 | 第 9 节 F-01 |
| 2 | `智能硬件管理 > 产品管理` → 选中今天要用的产品（`box1` 或 `小方块玩具`） | 该产品**已分配 License**（操作列仍有「分配 License」按钮通常说明**尚未分配**） | 第 9 节 F-02 |
| 3 | 同一行的「已关联智能体」列 | 显示 `默认智能体` | 第 9 节 F-03 |
| 4 | `智能体管理` → 点开 `默认智能体` | **使用模型**与**音色**都已选定（这一步最容易被漏） | 第 9 节 F-04 |
| 5 | 产品详情页 → 「产品密钥信息」 | 抄下 **实例 ID**、**ProductKey**、**ProductSecret** | — |

> ⚠️ **ProductSecret 等同密码**。只写进本机 `.env`，不要提交 git、不要贴聊天/工单。
> ⚠️ **一个产品只能分配一种规格的 License；一旦分配了 License，该产品就无法删除**。今天别乱点删除。

### 1.2 把凭证写进本项目（**不要**写进代码）

在仓库根目录 `.env` 中补全（`.env` 已被 `.gitignore` 排除）：

```ini
VOLCANO_API_BASE=https://rtc.volcengineapi.com
VOLCANO_ACCESS_KEY=<控制台「API 密钥管理」的 AccessKey>
VOLCANO_SECRET_KEY=<控制台「API 密钥管理」的 SecretKey>
VOLCANO_APP_ID=<控制台账号 ID>
```

### 1.3 平台侧录入云服务商并检测连通性

1. 起服务：`make dev` → 打开 `http://localhost:8000/platform/`
2. 用平台超管登录：账号 **`admin`**（密码见 `.env` 的 `PLATFORM_ADMIN_PASSWORD`）
3. 进入「云服务商配置」→ 编辑 `火山引擎智能云（硬件对话智能体）` → 填入上面三项 → 保存
4. 点「连通性检测」

| 检测结果 | 含义 | 下一步 |
|---|---|---|
| `result=NOT_CONFIGURED` | 地址或密钥没填全，**系统按安全策略跳过了真实调用**（不是报错） | 回到 1.3 第 3 步补全 |
| `ok=true` | **仅表示网络可达**，不代表密钥有效 | 继续 |
| `ok=false` | 网络不可达或厂商返回 5xx | 查本机网络/代理 |

> 这一步的意义：确认「未配置时安全失败、配置后网络可达」两条语义都在真实环境成立。

## 2. 硬件与工具链准备（10 分钟）

```bash
# 1) 串口烧录工具
pip3 install esptool
python3 -m esptool version          # 预期打印版本号

# 2) 官方开源工程（含最新设备端 SDK）
git clone https://github.com/volcengine/ConversationalAI-Embedded-Kit-2.0.git
cd ConversationalAI-Embedded-Kit-2.0/volc_conv_ai
ls                                  # 预期看到 cmake/ inc/ osal/ sample/ src/ third_party/ CMakeLists.txt
```

**硬件清单核对**：

- [ ] 开发板 + 数据线（喵伴用 USB A 转 Micro-B；Sense 按板子实际接口）
- [ ] 麦克风与喇叭（若板子需要外接）
- [ ] 手机或电脑（用于 Wi-Fi 配网）
- [ ] 串口驱动已装（若电脑识别不到串口：CH343 / CP210x 驱动）

**先确认电脑能看到串口**：

```bash
ls /dev/ttyUSB* /dev/ttyACM* 2>/dev/null    # Linux
```
- 有输出 → 记下设备名（如 `/dev/ttyUSB0`），下面命令里的 `--port` 用它
- 无输出 → 换线（很多线只能充电）、换口、装驱动；**这一步不通就不要往下做**

## 3. 路径 A：官方 Demo 板走开源工程（推荐，30 分钟）

适用：ESP32-S3-EchoEar（喵伴）/ ESP32-S3-Korvo-2。

1. 按工程 `README.md` 配置 ESP-IDF（官方工程已内置 SDK 与示例）
2. 在示例入口的配置里填入 **ProductKey / ProductSecret / 实例 ID**（通常是一个 `config_json` 或 menuconfig 项）
3. 编译并烧录（示例，具体以工程 README 为准）：

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor
```

4. 进入第 5 节「配网与首次对话」。

**预期串口日志顺序**（这是判断卡在哪一层的核心依据）：

```
on_volc_event(CONNECTED)                     ← 鉴权与长连接成功
on_volc_conversation_status(LISTENING)       ← 智能体就绪，可以说话了
（说一句话后）
on_volc_conversation_status(THINKING)        ← 云端在推理
on_volc_conversation_status(SPEAKING)        ← 开始下行音频
on_volc_audio_data(...)                      ← 喇叭出声
```

| 日志停在哪 | 说明 | 查 |
|---|---|---|
| 完全没有 `CONNECTED` | 网络或凭证问题 | 第 9 节 F-05 / F-06 |
| 有 `CONNECTED`、无 `LISTENING` | 智能体或许可证问题 | 第 9 节 F-02 / F-03 |
| 有 `SPEAKING`、无声音 | 音频输出链路（功放/喇叭）问题 | 第 9 节 F-07 |

## 4. 路径 B：预编译体验包（针对喵伴板，免搭环境）

> ⚠️ 官方声明：体验包**仅供快速体验**，且**无法修改音色、人设、function call**；要二次开发请用路径 A。

1. 下载体验包并解压，进入解压目录
2. 烧录（官方原文命令，注意 `--port` 按实际改）：

```bash
pip3 install esptool
python3 -m esptool --chip esp32s3 -b 460800 --before=default_reset --after=hard_reset \
  write_flash --flash_mode dout --flash_freq 80m --flash_size detect \
  0x0 bootloader.bin \
  0x10000 VolcRTCDemo.bin \
  0x8000 partition-table.bin \
  0x510000 srmodels.bin \
  0xb2e000 eaf.bin
```

3. 按住开关键开机 → 进入第 5 节配网。

> 体验包内置 **2 小时语音 + 30 万 tokens** 免费额度，与账号里的 10 个 License 是两套资源，别混淆。

## 5. Wi-Fi 配网（两种路径共用）

1. 手机 Wi-Fi 列表中找到热点 **`VolcConvAl-XXXXXX`** 并连接
   - **热点密码与热点名称相同**
2. 手机浏览器访问 **`http://192.168.4.1`**
3. 填入要连接的 Wi-Fi 名称与密码 → 提交
4. 设备重启后自动连网

**配网失败的两种情况**：

| 现象 | 原因 | 动作 |
|---|---|---|
| 找不到 `VolcConvAl-*` 热点 | 设备未进入配网模式（上电时序/开机键） | 断电重上电；确认已开机 |
| 提交后连不上，30 秒后又出现热点 | 保存的 Wi-Fi 连不上（密码错/信号差/5GHz） | 换 **2.4GHz** 网络重配（IoT 芯片普遍不支持 5GHz） |

> 换 Wi-Fi 需**先重启设备**；若重启后 30 秒内连不上已保存的 Wi-Fi，设备会自动重新进入配网模式。

## 6. 首次对话成功判据（三条同时满足才算通过）

- [ ] 串口出现 `CONNECTED` → `LISTENING`
- [ ] 对着设备说话，**能听到语音回应**
- [ ] 控制台 `智能硬件管理 > 设备管理` → 选中该产品 → **设备列表出现这台设备**（含 AI License 规格与用量统计）

> 第 3 条很关键：设备第一次激活会**自动绑定并使用一个 License**（从你分配的额度里扣 1 个）。控制台看到它，说明「云端认账」，后面做本项目 P4/P5 的设备链路才有真实依据。

## 7. 路径 C：ESP32-S3 Sense 自行移植（今天的目标是「跑通连接测试」）

**不要在今天承诺做到对话**。把目标定成官方移植指南的验收点：**构建出静态库 + 跑通连接测试**。

移植工作分两类（详见 `docs/13` §4.5 与官方《高质量方案设备端 SDK 移植指南》）：

| 类别 | 内容 | 是否需要改 |
|---|---|---|
| 直接引用 | `volc_rtc_engine`（`src/transports/high_quality/third_party/volc_rtc_engine_lite`）、连接逻辑（`cmake/common.cmake`） | 否 |
| 外部依赖 | `mbedtls`（加密）、`cJSON`（JSON，源码在 `src/util/cJSON`） | 需引入 |
| **自研** | ① 系统抽象层 OSAL（线程/互斥锁/内存分配，参考 `osal/src` 的 Linux 实现）② CMake 交叉编译工具链 ③ **板级音频采集与播放链路** | 是 |

**执行顺序（每一步都先让它单独通过）**：

1. 先用 `sample/sample.c` 在**电脑（macOS/Linux 参考实现）**上编译跑通，确认工程本身没问题
2. 交叉编译到 ESP32-S3，**只验证能出静态库**（不接音频）
3. 接 `volc_create` → `volc_start`，**只验证串口出现 `CONNECTED`**（此时还没有音频，正常）
4. 最后再做 I2S/PDM 麦克风与功放输出（这一步是纯硬件适配，最耗时）

**如果第 2 步就卡住超过 1 小时** → 切到路径 D，不要在工具链上耗掉整个晚上。

## 8. 路径 D：低负载方案（WebSocket 标准协议）

适用：板级音频链路不匹配、或想绕开 C SDK 移植。

- 官方入口：文档《通过标准协议自定义接入》
- 官方明确提示：**需要自行处理鉴权签名、连接保活、协议封装**
- 优点：TCP/WebSocket，内存占用 < 100KB，对 Sense 这类板子更友好
- 代价：没有官方 SDK 的现成回调，`CONNECTED`/`LISTENING` 这类状态要自己实现

> 我们平台侧 P7 的 `ai/volcano.py` 已按官方 Action 形态封装好服务端接口（`Aibot*` 系列），
> 但**签名算法仍是占位**——真正联调时先按官方《调用方法》把签名替换掉，再考虑把真机接进来。

## 9. 失败速查表（现象 → 必须先查的一条）

| 编号 | 现象 | 最可能原因 | 具体动作 |
|---|---|---|---|
| F-01 | 控制台看不到额度 | 产品未开通/未授权 | 确认 `conversational-ai-embedded` 控制台已开通并有授权 |
| F-02 | 设备连上但无响应 / 无 `LISTENING` | **产品未分配 License** | 产品列表 → 操作 → 分配 License（先用基础版 × 1） |
| F-03 | 同上 | **产品未关联智能体** | 产品列表 → 「已关联智能体」列 → `+ 关联智能体` → 勾选 `默认智能体` |
| F-04 | 能连上但设备"装聋作哑" | **智能体的模型/音色未配置** | 智能体管理 → 打开该智能体 → 选好 使用模型 与 音色 |
| F-05 | 无 `CONNECTED` | Wi-Fi 未连上 / 5GHz | 重启进配网；改连 2.4GHz |
| F-06 | 无 `CONNECTED` | ProductKey / ProductSecret 填错 | 回产品详情页逐字核对（注意区分 ProductSecret 与 DeviceSecret） |
| F-07 | 有 `SPEAKING` 但无声音 | 功放/喇叭/音频编解码配置 | 先用官方 Demo 板验证硬件链路本身是否正常 |
| F-08 | 对话中途断开 | 弱网（低负载方案对弱网不友好） | 换高质量方案或改善网络 |
| F-09 | 额度消耗异常快 | 联调期间长时间挂机（按交互时长计费） | 设备详情页看「用量统计」进度条；不用时断电 |
| F-10 | 改音色改不了 | 用的是体验包 | 体验包不支持定制，改用开源示例工程 |

## 11. 今天的三条纪律（避免踩坑）

1. **先云后硬**：步骤 1–3 不通过就不要碰硬件——否则硬件出问题时无法判断是不是云的问题。
2. **不在今天承诺 Sense 板的完整对话**：官方 Demo 板与 Sense 板的工作量差一个量级，把 Sense 的目标定成「构建 + 连接测试」。
3. **凭证只进 `.env`**：ProductSecret / DeviceSecret / AccessKey / SecretKey 一律不进 git、不进聊天记录；本项目 `.env` 已被 `.gitignore` 排除，且平台侧响应**只回掩码**，不会因为截图泄漏。
